# 环境监测小时观测数据平台

FastAPI + SQLite 的网页应用：测站结构（列名/列型）随时间演化，旧批次观测数据
仍可按**现役列名**统一查询，也可切回**历史版本**查看当时的列名与原始读数。
在此之上提供**按 UTC 周 / 站号 / 稳定列标识的小时抽样清单**，供实验室盲核使用。

## 功能

- **发布初版结构**：自定义站号列、UTC 小时列与数据列（整数 / 小数 / 文本）。
- **按现役结构上传 CSV**：表头须与现役结构一致（顺序不限），逐行校验类型，
  任何一行不合格则**整批拒绝**，不产生半成品批次。
- **结构演化（发布新版本）**，只允许三类安全变更：
  - 改列名（含站号/小时列，跨多版连续改名也能找回旧值）；
  - 新增**可空**列（旧批次该行显示空值）；
  - 整数列**扩型**为小数列（旧值原样保留，不做任何换算）。
- **拒绝并回滚**：删除旧列、两列合并、一列拆多列、缩型（小数→整数等）、
  改系统列类型、新增非空列、列名重复——全部拒绝，现役版本与供数不受影响。
- **统一查询**：按站号 + UTC 小时区间查询，所有批次用现役列名展示。
- **历史视角**：选择任一历史版本，只看该版批次，列名与读数都是当时的样子。
- **交错安全**：发布 / 上传 / 查询均在全局锁 + 单事务内完成，结构与数据不混用。
- **抽样清单**（页面 ⑦⑧）：
  - 按 **UTC 周**（周一 00:00 起 168 小时）+ **站号** + **稳定列标识**（如 `c1`）生成；
    周可写 `2026-W47`、`2026-W47-2`、`2026-11-16` 或周内任一小时。
  - 每站每周抽取指定数量的**有值小时**；空值小时仅作候选记录，不参与抽取。
  - **同站同小时重复上传只占一个候选位置**：各批次读数一致（数值按十进制比较，
    `5` 与 `5.0` 相同）视为同一候选并记录全部原始批次；读数不一致列为**待核**，
    保留每一条异值明细并排除抽样。
  - 用**可复现种子** + `sha256(seed|周|列|站|小时)` 排序键从合格小时中等概率抽取；
    种子可人工指定或自动生成，生成值写入清单，可据此复算。
  - 清单发布后为**快照**：当时的候选范围、选中读数、原始批次号与结构版本原样保留，
    之后的补传 / 换版不会改动旧清单。
  - 已交站点小时**跨轮次锁定**（`sampling_claims` 以站号+小时为主键）：新轮次按新范围
    抽取，但不再领用前轮已交的站点小时；名额不足时在站级汇总中写明**缺额与原因**
    （合格不足 / 待核 / 前轮已领用 / 空值 / 已交样本被改动）。
  - 补传改动已交读数时，新轮次只在清单里**告警**（同小时出现多个异值时同时列入待核），
    绝不悄悄替换旧清单里已交的读数。
  - 抽样与上传 / 换版共享同一 `session()` 事务（`BEGIN IMMEDIATE`）：
    候选范围、已领样本与清单来自同一已提交状态；任何失败整体回滚，
    不占用名额、不产生半截清单、不改旧清单。

## 快速开始（Docker Compose）

```bash
docker compose up --build
# 打开 http://localhost:8000
```

数据保存在命名卷 `obs-data` 中（容器内 `/srv/data/obs.db`）。

## 本地开发

```bash
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --reload
# 打开 http://127.0.0.1:8000
```

## 自测

```bash
python tests/selftest.py           # 结构版本 / 上传 / 查询：39 项
python tests/sampling_selftest.py  # 抽样清单：重复上传 / 补传 / 换版 / 失败回滚：88 项
```
退出码 0 为通过。

## 页面操作流程（可用 examples/ 下的样例 CSV）

1. 「② 发布结构版本」发布初版：站号=`站号`，小时=`UTC小时`，数据列 `气温`(整数)、`气压`(整数)。
2. 「③ 上传」选择 `examples/v1_初版结构.csv`。
3. 「②」把 `气温` 改名为 `气温_C`、`站号` 改名为 `station_code`、`气压` 扩型为小数 → 发布 v2；上传 `examples/v2_改名扩型后.csv`。
4. 「②」把 `气温_C` 改名为 `温度`，新增可空列 `湿度`(整数) → 发布 v3；上传 `examples/v3_再加列后.csv`。
5. 「④ 查询」现役视角：v1 批次的 `温度` 列仍显示当年的 5/6/3，`湿度` 显示空值，`气压` 仍是整数 1013/1012/1015。
6. 「⑤ 版本历史」点 v1「以此视角查询」：只看到 v1 批次，列名是 `站号/气温/气压`，读数原样。
7. 「⑦ 抽样清单」填 `2026-W47`、选 `温度`（或缩小到 `c1`），每站 2 个，种子留空自动生成 →
   生成清单，展开可看各站情况、缺额、选中读数与全部候选，点「下载 CSV」导出。
8. 再上传重复 / 异值数据后重新生成一轮，可看到「前轮已领用」「待核」「已交样本被改动」的标注；
   旧清单数值与候选范围保持不变。

## API 一览

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/versions` | 全部版本（含列定义） |
| GET | `/api/versions/current` | 现役版本 |
| GET | `/api/versions/{no}` | 指定版本 |
| POST | `/api/versions` | 发布新版本（初版或演化），非法变更 400 |
| POST | `/api/batches` | 上传 CSV（multipart，字段名 `file`），校验失败 400 且整批回滚 |
| GET | `/api/batches` | 批次列表 |
| GET | `/api/observations` | 查询：`station`、`hour_from`、`hour_to`、`version_no`（缺省=现役视角）、`limit` |
| GET | `/api/sampling/meta` | 当前 UTC 周、可抽样列（含稳定列标识）、全部已领用样本 |
| GET | `/api/sampling/rounds` | 清单列表，可选 `week=2026-W47` 过滤 |
| POST | `/api/sampling/rounds` | 生成并发布一轮清单（请求体见下），失败 400 且整体回滚 |
| GET | `/api/sampling/rounds/{id}` | 清单快照：站级汇总（含缺额原因）、全部候选、选中读数、待核明细 |
| GET | `/api/sampling/rounds/{id}/csv` | 下载清单 CSV（UTF-8 BOM，含原始批次与结构版本） |

生成抽样清单请求体示例：

```json
{
  "week": "2026-W47",
  "column_id": "c1",
  "per_station": 2,
  "seed": "lab-batch-2026-47",
  "note": "第 47 周盲核",
  "stations": ["S01", "S02"]
}
```

`week` 也接受 `2026-11-16` / `2026-11-16T05:00` / `2026-W47-3`（归到所属 UTC 周）；
`seed` 省略时自动生成并写入清单；`column_id` 是稳定列标识（页面上可选列名旁的 `c1` 等）；
`stations` 可省略（缺省 = 本周有数据的站）；显式点名但本周无数据的站会出现在清单中并记全额缺额。

发布新版本请求体示例（演化）：

```json
{
  "note": "改名+扩型+加列",
  "columns": [
    {"source": "station", "name": "station_code"},
    {"source": "hour_utc", "name": "UTC小时"},
    {"source": "c1", "name": "温度"},
    {"source": "c2", "name": "气压", "type": "float"},
    {"source": null, "name": "湿度", "type": "integer", "nullable": true}
  ]
}
```

初版用 `{"role": "station"/"hour"/"data", "name": ..., "type": ...}` 声明列。

## 设计说明

- **列血缘**：每个逻辑列有稳定标识 `column_id`（`station` / `hour_utc` / `c1` / `c2` …）。
  改名、扩型复用同一 `column_id`，因此改名链跨多版仍可定位旧值。
- **原值存储**：观测值按上传时的解析结果存入 `observations.values_json`
  （`{column_id: value}`），之后任何版本操作都不改写它。新增列在旧行自然为空；
  扩型不回填（旧整数仍是整数，数值不变）。
- **事务与锁**：所有读写经 `db.session()`（全局 RLock + 单连接事务）。
  发布/上传先完整校验再写入，失败整体回滚——失败操作后仍按原版本供数。
- **小时规范化**：`2026-11-18 03:00`、`2026-11-18T03:00:00Z` 等写法统一规范为
  `YYYY-MM-DDTHH:MM` 存储，区间查询按字典序比较（规范后等价于时间序）。
- **抽样快照**：`sampling_rounds` 记录周范围、列标识与当时的列名/类型、结构版本号、种子与算法；
  `sampling_candidates` 记录该轮每个 (站号,小时) 的状态、全部原始读数、是否抽中及选中读数；
  `sampling_claims` 以 (站号,小时) 为主键跨轮次占位；`sampling_station_summaries` 记录站级缺额与原因。
  这些都只写不改——补传和换版只影响之后新生成的轮次。
- **抽样事务**：`create_round` 在同一 `session()` 事务里读取候选与已领样本、写清单与领用记录，
  失败整体回滚；`BEGIN IMMEDIATE` 让并发生成串行化，不会出现两轮同时领用同一站点小时。

## 已知限制

- 单进程 + SQLite，适合单站/小团队部署；多实例水平扩展需换外部数据库。
- 历史视角只显示该版本上传的批次（“当时的列名与当时的读数”），不把新批次映射进旧结构。
- 小时列按整点/分钟对齐，秒级或非 ISO 写法会被拒绝。
- 抽样范围按周时间区间 `[周一 00:00, 下周一 00:00)` 匹配（上传时小时已规范化到分钟）；
  同一站同一小时的多条批次只在生成清单时归并，原始批次记录本身仍完整保留。
- 已领用锁定按 (站号, 小时) 跨列生效：同一站点小时即使换列抽也不再发放，以免把已交样本
  换个列名重复交给实验室。
- 清单发布后不支持撤销 / 改选；若确需重抽，应换一个新种子生成新一轮，旧清单保持可追溯。
